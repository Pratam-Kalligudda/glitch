done_when: "A Checker test runs with a fake Fetcher, makes no network call, and fails with a clear message when you break the retry loop."

A test that reaches the real network is slow, depends on a server you do not control, and cannot easily produce the failures you most need to test: a timeout, a 500, a connection reset. The answer is to give the code under test an **interface** for the one thing it needs from the outside world, and in tests hand it a stand-in. A stand-in is a **test double**. The common kinds:

| Kind | What it does |
|---|---|
| **Stub** | Returns fixed answers |
| **Fake** | A small working implementation with shortcuts, such as a map instead of a database |
| **Spy** | Records how it was called, so the test can check the calls afterwards |
| **Mock** | Checks calls against expectations declared in advance, usually generated by a tool |

In Go you rarely need a mock framework. The interface is the seam, and a short hand-written struct is usually a stub, fake and spy at once. The rules for the interface itself are in [[accept-interfaces]]: a consumer declares the small interface it needs. A test double is the best proof that this works.

## The seam: one small interface

linkcheck decides whether a link is broken from one fact, the HTTP status, and it should not care how the status was obtained. That is the `Fetcher` interface:

```text title="go.mod"
module example.com/doubles

go 1.27
```

```go title="check.go"
// Package check reports which URLs in a list are broken.
package check

import (
	"context"
	"errors"
	"fmt"
)

// Fetcher gets one URL and reports its HTTP status. It is the only thing
// Checker needs from the network, so tests can replace it.
type Fetcher interface {
	Fetch(ctx context.Context, url string) (status int, err error)
}

// Result is the outcome for one URL.
type Result struct {
	URL    string
	Status int
	Err    error
}

// Broken reports whether the link needs attention.
func (r Result) Broken() bool { return r.Err != nil || r.Status >= 400 }

// Checker checks URLs with a Fetcher.
type Checker struct {
	Fetcher Fetcher
	Retries int // extra attempts after a failed fetch
}

// Check fetches url, retrying on error up to c.Retries more times.
func (c *Checker) Check(ctx context.Context, url string) Result {
	var err error
	for attempt := 0; attempt <= c.Retries; attempt++ {
		var status int
		status, err = c.Fetcher.Fetch(ctx, url)
		if err == nil {
			return Result{URL: url, Status: status}
		}
		if errors.Is(err, context.Canceled) {
			break
		}
	}
	return Result{URL: url, Err: fmt.Errorf("check %s: %w", url, err)}
}

// CheckAll checks every URL in order and stops early if ctx is cancelled.
func (c *Checker) CheckAll(ctx context.Context, urls []string) []Result {
	var out []Result
	for _, u := range urls {
		if ctx.Err() != nil {
			break
		}
		out = append(out, c.Check(ctx, u))
	}
	return out
}
```

`Checker` holds a `Fetcher`, not an `*http.Client`. In production, a type that wraps `http.Client` satisfies it ([[http-client]]); the real one is the capstone's job in [[step-1-single-page]]. In a test, anything with the one method will do.

## A fake that also spies

```go title="check_test.go"
package check

import (
	"context"
	"errors"
	"fmt"
	"sync"
	"testing"
)

// fakeFetcher answers from a table and records every call.
type fakeFetcher struct {
	mu     sync.Mutex
	status map[string]int     // URL -> status to return
	errs   map[string][]error // URL -> errors to return first, one per call
	calls  []string
}

var _ Fetcher = (*fakeFetcher)(nil)

func (f *fakeFetcher) Fetch(ctx context.Context, url string) (int, error) {
	f.mu.Lock()
	defer f.mu.Unlock()
	f.calls = append(f.calls, url)
	if q := f.errs[url]; len(q) > 0 {
		f.errs[url] = q[1:]
		return 0, q[0]
	}
	status, ok := f.status[url]
	if !ok {
		return 0, fmt.Errorf("fakeFetcher: no response configured for %s", url)
	}
	return status, nil
}

func TestCheckStatus(t *testing.T) {
	f := &fakeFetcher{status: map[string]int{
		"https://go.dev/":        200,
		"https://go.dev/missing": 404,
	}}
	c := &Checker{Fetcher: f}

	tests := []struct {
		url        string
		wantBroken bool
	}{
		{"https://go.dev/", false},
		{"https://go.dev/missing", true},
	}
	for _, tc := range tests {
		got := c.Check(t.Context(), tc.url)
		if got.Broken() != tc.wantBroken {
			t.Errorf("Check(%q).Broken() = %t, want %t (%+v)", tc.url, got.Broken(), tc.wantBroken, got)
		}
	}
}

func TestCheckRetries(t *testing.T) {
	errTimeout := errors.New("timeout")
	f := &fakeFetcher{
		status: map[string]int{"https://go.dev/": 200},
		errs:   map[string][]error{"https://go.dev/": {errTimeout, errTimeout}},
	}
	c := &Checker{Fetcher: f, Retries: 2}

	got := c.Check(t.Context(), "https://go.dev/")
	if got.Broken() {
		t.Fatalf("Check = %+v, want success on the third attempt", got)
	}
	if len(f.calls) != 3 {
		t.Errorf("Fetch called %d times, want 3", len(f.calls))
	}
}

func TestCheckGivesUp(t *testing.T) {
	errTimeout := errors.New("timeout")
	f := &fakeFetcher{errs: map[string][]error{"u": {errTimeout, errTimeout, errTimeout}}}
	c := &Checker{Fetcher: f, Retries: 1}

	got := c.Check(t.Context(), "u")
	if !errors.Is(got.Err, errTimeout) {
		t.Fatalf("Err = %v, want it to wrap %v", got.Err, errTimeout)
	}
	if len(f.calls) != 2 {
		t.Errorf("Fetch called %d times, want 2", len(f.calls))
	}
}

func TestCheckAllStopsWhenCancelled(t *testing.T) {
	ctx, cancel := context.WithCancel(t.Context())
	f := &fakeFetcher{status: map[string]int{"a": 200, "b": 200, "c": 200}}
	c := &Checker{Fetcher: f}

	cancel()
	if got := c.CheckAll(ctx, []string{"a", "b", "c"}); len(got) != 0 {
		t.Errorf("CheckAll returned %d results after cancel, want 0", len(got))
	}
	if len(f.calls) != 0 {
		t.Errorf("Fetch called %d times after cancel, want 0", len(f.calls))
	}
}
```

## How it works

**The fake is a few lines of ordinary Go.** `status` says what each URL answers. `errs` is a queue of errors to return *before* the real answer, one per call: two `errTimeout` entries make the first two attempts fail and the third succeed. That is how you test a retry loop, because a real server fails when it likes, not when the test needs it. `calls` records the URL of every call, which turns the fake into a spy: `TestCheckRetries` asserts three calls and `TestCheckAllStopsWhenCancelled` asserts none.

**`var _ Fetcher = (*fakeFetcher)(nil)` is a compile-time check.** It assigns a nil `*fakeFetcher` to the blank identifier typed as `Fetcher`. If the fake ever stops satisfying the interface, for example because `Fetch` gains a parameter, the error appears on this line, not at some distant use.

**An unexpected call fails loudly.** When a URL has no configured answer, the fake returns an error that says so, instead of a zero status that would look like a valid response. A fake that silently answers anything lets a test pass for the wrong reason.

**The mutex is there for later.** These tests are sequential, but a `Checker` that runs a worker pool calls `Fetch` from many goroutines ([[worker-pools]]), and an unguarded `append` to `calls` is then a data race ([[mutexes]]). A fake that is used concurrently must be safe to call concurrently; [[coverage-race]] shows the race detector catching one that is not. Reading `f.calls` from the test, as here, is safe only after the calls have finished.

**The test stays in control of time and errors.** `t.Context()` gives each test a context ([[test-helpers]]). `TestCheckAllStopsWhenCancelled` cancels it first and checks that no fetch happens.

### A function as a fake

When the double is one method, a function type is lighter than a struct. This is the pattern `http.HandlerFunc` uses for `http.Handler`:

```go title="func_test.go"
package check

import (
	"context"
	"testing"
)

// fetcherFunc lets a plain function satisfy Fetcher, as http.HandlerFunc does
// for http.Handler.
type fetcherFunc func(ctx context.Context, url string) (int, error)

func (f fetcherFunc) Fetch(ctx context.Context, url string) (int, error) {
	return f(ctx, url)
}

func TestCheckPassesContext(t *testing.T) {
	type key struct{}
	ctx := context.WithValue(t.Context(), key{}, "marker")

	c := &Checker{Fetcher: fetcherFunc(func(ctx context.Context, url string) (int, error) {
		if ctx.Value(key{}) != "marker" {
			t.Error("Fetch did not receive the caller's context")
		}
		return 200, nil
	})}
	c.Check(ctx, "https://go.dev/")
}
```

Use the function form when each test needs its own behaviour in a few lines, such as asserting on the arguments. Use the struct form when several tests share a table of answers or need the call log.

## What a failure looks like

Change the loop condition in `Check` from `attempt <= c.Retries` to `attempt < c.Retries`. This is the off-by-one that makes `Retries: 0` mean no attempts at all:

```text
--- FAIL: TestCheckStatus (0.00s)
    check_test.go:53: Check("https://go.dev/").Broken() = true, want false ({URL:https://go.dev/ Status:0 Err:check https://go.dev/: %!w(<nil>)})
--- FAIL: TestCheckRetries (0.00s)
    check_test.go:68: Check = {URL:https://go.dev/ Status:0 Err:check https://go.dev/: timeout}, want success on the third attempt
--- FAIL: TestCheckGivesUp (0.00s)
    check_test.go:85: Fetch called 1 times, want 2
FAIL
FAIL	example.com/doubles	0.321s
FAIL
```

Three tests fail, each from a different angle: the result says broken without any error (the `%!w(<nil>)` is `fmt.Errorf` formatting a nil error), the retry count is short by one, and the call count is wrong. Printing the whole `Result` with `%+v` made the first failure readable without a debugger. Restoring `<=` brings back `ok`.

> [!WARNING]
> Over-specifying a double makes tests brittle. A mock that expects "`Fetch` is called exactly once with these arguments, in this order" fails when you refactor the code without changing its behaviour. Symptom: a harmless internal change turns many tests red. Fix: assert on outcomes (the results returned, the number of attempts when that is the behaviour) and make the fake answer by input, not by call order. The second trap is a big interface. A `Fetcher` with eight methods needs an eight-method fake. Declare, in the consumer, only the one or two methods it calls.

> [!NOTE]
> Passing the double in as a field or a parameter is plain dependency injection, with no framework. Avoid replacing package-level variables (`var fetch = http.Get` swapped in a test): it leaks between tests, forbids `t.Parallel`, and is a data race if any goroutine is still running. If the code under test uses `net/http` directly and you would rather exercise the real client against a local server, that is the next stop: [[httptest]].

linkcheck's `Crawler` takes a `Fetcher` so that its step 6 tests can run the whole crawl in memory; see [[step-6-tests]].
